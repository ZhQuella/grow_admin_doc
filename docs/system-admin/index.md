# 系统管理

Grow Admin 在 DesignCornerstone 中提供 **基础服务（系统管理）** 模块：覆盖组织、人员、账号、角色、菜单与权限配置，以及组织架构可视化。所有页面落点 **`@grow-admin-cornerstone/apps-system`**（`DesignCornerstone/cornerstone-apps-system`），由宿主 `sample` 经 IOC 装配后，登录即可在侧栏 **系统管理** 菜单下访问。

::: tip 演示入口
登录 [Demo](https://demo.gadmin.top/) 后打开侧栏 **系统管理**。本地需在宿主装配 `@grow-admin-cornerstone/apps-system` 并启用对应 Mock。
:::

## 业务地图

```text
组织主线：部门 → 岗位 / 职级 → 人员任职 → 组织架构图

批量主线：导入导出规格 → 批量维护组织、人员与权限数据
```

与框架文档的衔接：动态路由与菜单机制见 [路由与菜单](/guide/architecture/routing-and-menu)；权限模式见 [权限模式](/guide/development/permission-mode)。

## 设计口径

| 原则 | 说明 |
|------|------|
| 部门、岗位、人员解耦 | 部门、岗位、人员之间不直接写死关系，而是通过 **任职关系** 连接，支持一人多部门、一人多岗位、主岗与兼岗、调岗历史、返聘、岗位编制，以及部门停用 / 迁移 / 合并后的历史追溯。 |
| 岗位归属于部门 | 岗位由部门自行维护，不做全局岗位库。岗位数量通过 **编制** 表达，不创建多条同名岗位记录。 |
| 职级全局独立维护 | 职位与职级在本系统表达同一概念，界面统一称为「职级」。职级是全局基础数据；**岗位与职级不绑定**，人员任职时分别选择。 |
| 权限以账号和角色为核心 | 角色不直接绑定部门、岗位或人员。 |

```text
权限链路：账号 → 角色 → 菜单权限 / 功能权限 / 数据权限
组织链路：账号 → 绑定人员 → 任职关系 → 部门 / 岗位 / 上下级
```

## 核心关系模型

```text
部门
  └── 岗位

人员
  └── 任职关系
        ├── 部门
        ├── 岗位
        ├── 职级
        ├── 主职/兼职
        └── 历史记录

账号
  ├── 绑定人员
  └── 绑定角色

角色
  ├── 菜单权限
  ├── 功能权限
  ├── 行权限
  └── 列权限

菜单
  ├── 功能权限定义
  └── 表定义
        └── 字段定义
```

## 全局业务规则（摘要）

| 范围 | 规则 |
|------|------|
| 组织基础 | 部门支持多级结构；岗位归属于部门；职级全局维护。 |
| 任职关系 | 人员必须通过任职关系绑定部门和岗位；必须且只能有一个主岗位；主岗位所属部门自动作为主部门。 |
| 汇报关系 | 人员可多部门、多岗位、多上级；上下级关系单独维护在任职上。 |
| 编制统计 | 岗位超编只提示，不阻止；兼职不占用编制。 |
| 账号状态 | 人员离职后账号自动停用；账号与人员一对一。 |
| 角色授权 | 角色绑定账号；多角色权限取并集；列权限冲突时可见优先。 |
| 删除联动 | 菜单 / 功能权限删除时，相关授权一并删除。 |

完整规则与状态联动见 [权限联动与通用规则](/system-admin/permission-rules)。
